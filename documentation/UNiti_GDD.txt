1. GAME OVERVIEW
1.1 Concept
An online multiplayer hero arena game inspired by Nigerian mythology, traditional
spiritual systems, folklore and contemporary Nigerian environments.
Players enter a multiplayer lobby, select a playable champion, choose a spiritual
patron, customise their combat loadout and compete against other players in
team-based arena matches.
The game combines:
Nigerian mythology and cultural inspiration.
Distinctive playable champions.
UNiti
1
Patron-based spiritual progression.
Fast, ability-driven combat.
Competitive team gameplay.
Nigerian-inspired environments.
Character cosmetics and seasonal progression.
Online social features and competitive rankings.
Players do not necessarily play as the gods themselves. They play as champions
who receive power through their selected spiritual patron.
1.2 Design pillars
Combat first: Responsive, readable and rewarding gameplay.
Nigerian identity: Distinctive Nigerian cultural, environmental, architectural and
musical influences.
Meaningful customisation: Different champion, patron and charm combinations.
Competitive fairness: Skill and teamwork matter more than money spent.
Expandability: New champions, patrons, arenas and game modes must be
addable without rewriting existing systems.

Patronage is the game's defining progression feature.

8. GAME MODES

13. GODOT TECHNICAL ARCHITECTURE
13.1 Game engine
Mandatory engine: Godot 4.x.
Use the latest stable Godot 4.x version available and supported in the
development environment.
Pin the exact version in the README and development documentation.
Primary language: GDScript.
Do not introduce C# unless a specific technical requirement justifies it.
UNiti
17
Do not use Unity, Unreal, Unity Netcode, Unity-specific packages or Unity project
structures.
13.2 Rendering
Use Godot's 3D rendering pipeline.
Choose the renderer based on actual target-device testing:
Mobile renderer for a mobile-first performance baseline.
Compatibility renderer where broader low-end hardware support is necessary.
Forward+ where desktop visual requirements justify it.
Start with a practical renderer and test on the intended hardware early.
Avoid committing to expensive lighting, shadows and effects before Android
performance has been measured.

13.6 Networking architecture

multiplayer prototype.
The server must be authoritative.
The server owns and validates:

Match state.
Ability activation.
Cooldowns.
Hit validation.
Objective state.
Team score.
Respawn.
Match completion.

UNiti
20
Use RPCs carefully, with explicit authority, validation and ownership checks.
Use MultiplayerSpawner and MultiplayerSynchronizer where appropriate, rather
than manually synchronising every replicated object without a clear reason.
Build a small multiplayer proof of concept first.
Test latency, packet loss, disconnections, reconnection and server performance
before expanding the player count.
Client-side prediction and server reconciliation may be introduced after
authoritative server simulation is working.
Do not assume that using ENet automatically makes a game cheat-resistant.
Implement input validation, rate limits and server-side gameplay checks.
13.7 Dedicated server
Godot 4 supports running projects in headless mode and exporting dedicated-
server builds.
Create a dedicated server export preset.
The server must run without rendering gameplay graphics or requiring a display.
Separate the client presentation layer from server gameplay logic so server
instances do not load unnecessary visual assets.
Provide documented commands for starting a local server and connecting
multiple client instances.

20. RISKS AND IMPORTANT DECISIONS
Scope: Prioritise combat before expanding the character catalogue or store.
Networking: Test ENet and dedicated server performance early. Do not assume
local multiplayer proves production readiness.
Cultural representation: Maintain the distinction between Nigerian traditions. Get
cultural review before final representations.
Monetisation: Cosmetics and optional seasonal progression only. No paid combat
advantages or gambling-style loot boxes.
Mobile performance: Benchmark early on representative Android devices.

game loop is functional.
